## ⭐ 核心认知：接口 ≠ 实现

**这个项目最重要的一句话：**

> **栈和队列是「接口」（规定怎么进怎么出），数组和链表是「实现」（规定数据存在哪里）。**

| 接口 | 规则 | 本项目用什么实现 |
|---|---|---|
| **栈 Stack** | **LIFO** 后进先出 | 动态数组 |
| **队列 Queue** | **FIFO** 先进先出 | 链表 |

**但这不是唯一的组合：**

```
栈  可以用数组实现 ✅（本项目）    也可以用链表实现 ✅
队列 可以用链表实现 ✅（本项目）    也可以用数组实现 ✅（叫"循环队列"）
```

**你写的 `stack_push` 和项目 3 的 `da_push` 几乎一模一样——因为你只是在用数组实现栈。**

> 这就是"抽象数据类型（ADT）"的概念：**同一个接口，可以换不同的底层实现。**

## 📊 图示：栈 vs 队列

### 栈（LIFO）—— 像一摞盘子

```
入栈 push          出栈 pop
    ↓                ↑
 ┌──────┐        ┌──────┐
 │  30  │ ← 栈顶  │      │
 ├──────┤        ├──────┤
 │  20  │        │  20  │
 ├──────┤        ├──────┤
 │  10  │        │  10  │
 └──────┘        └──────┘
   只能从顶上进出

入 10, 20, 30  →  出 30, 20, 10   （反着出来）
```

### 队列（FIFO）—— 像排队买饭

```
出队 pop ←  [10][20][30]  ← 入队 push
             ↑front   ↑rear

入 10, 20, 30  →  出 10, 20, 30   （按顺序出来）
```

## 📝 Part A：栈（动态数组实现）

### A1. `stack_create`
和 `da_create` **一模一样**：两次 `malloc`，都判空，初始容量 4。

### A2. `stack_push`（入栈）
**和 `da_push` 一模一样**：

```
① 满了就扩容（容量翻倍，realloc 先存 tmp）
② data[size] = val;  size++;
```

**因为栈顶就是数组的最后一个元素——入栈 = 往数组末尾追加。**

### A3. `stack_pop`（出栈）⭐
```c
if (s->size == 0) return -1;      /* 空栈保护 */
s->size--;                         /* 先减 */
return s->data[s->size];           /* 再取 */
```

**⚠️ 想清楚"先减再取"还是"先取再减"：**

```
栈内 [10, 20, 30]，size = 3，栈顶是 data[2] = 30

先减再取：size 变 2，取 data[2] = 30   ✅ 正确
先取再减：取 data[3] ← 越界了！        ❌ 错误
```

**因为 `size` 是"个数"，栈顶的下标是 `size - 1`。**

### A4. `stack_top`（看栈顶）
```c
if (s->size == 0) return -1;
return s->data[s->size - 1];       /* 注意是 size - 1 */
```
**只是"看"，不改 `size`。**

### A5-A6. `stack_empty` / `stack_size`
一行：`return s->size == 0;` / `return s->size;`

### A7. `stack_free`
```c
if (s == NULL) return;
free(s->data);      /* 先内层 */
free(s);            /* 再外层 */
```

## 📝 Part B：队列（链表实现）

### B1. `queue_create`
**只有结构体，没有数组**——节点是后面入队时一个个 `malloc` 的。

```c
q->front = NULL;    /* 队头 */
q->rear  = NULL;    /* 队尾 */
q->size  = 0;
```

### B2. `queue_push`（入队：加到队尾）

```
① 造新节点 n
② 分两种情况：
   队列是空的（q->rear == NULL）
       → q->front = q->rear = n;
   队列非空
       → q->rear->next = n;      （旧队尾指向新节点）
         q->rear = n;            （新节点成为新队尾）
③ q->size++;
```

**⭐ 为什么要维护 `rear` 指针？**

| 做法 | 入队复杂度 |
|---|---|
| 不存 `rear`，每次从头走到尾 | **O(n)** |
| **存 `rear`，直接接上去** | **O(1)** |

**多存一个指针，换来 O(n) → O(1)。** 这和项目 3 里"多存一个 `capacity`"是同一个思想。

### B3. `queue_pop`（出队：从队头拿走）⭐

```c
if (q->front == NULL) return -1;          /* 空队列 */
int val = q->front->data;
QNode *old = q->front;
q->front = old->next;
free(old);                                 /* 先接链子再 free */
q->size--;
if (q->front == NULL) q->rear = NULL;      /* ⚠️ 最容易忘的一步！ */
return val;
```

**⚠️ 最后那一步是这个项目最容易错的坑：**

```
出队前:  front → [10] → NULL
                 rear ↑（也指向 10）

出队后（如果忘了清 rear）:
         front → NULL
         rear  → [10]（已释放的内存！悬空指针）

         front  → [99]        ← 下次入队时：
         rear   → [10] 已释放  ← 新节点接到"已释放的内存"上 → 崩溃
```

**队列空了，`front` 和 `rear` 必须同时是 `NULL`——因为"空队列"的定义就是两者都为 `NULL`。**

### B4-B6. `queue_front` / `queue_empty` / `queue_size`
都很简单。`queue_empty` 的判断是 `q->front == NULL`。

### B7. `queue_free`
从头到尾把每个节点 `free`（和 `list_free` 一样，**先存 `next` 再 `free`**），最后 `free(q)`。

## 📝 Part C：括号匹配（用栈解决）

### 思路

```
遍历字符串：
  遇到左括号 ( [ {     → 入栈
  遇到右括号 ) ] }     → 看栈顶是不是【对应的】左括号
                          是   → 弹栈
                          不是 → 不匹配（比如 "(]"）
                          栈空 → 不匹配（右括号多了）

扫完之后：栈必须是空的（否则左括号多了）
```

### 为什么用栈？

**因为括号是"最近打开的，最先关闭"——这正是 LIFO。**

```
"([{}])"

遇到 (  → 栈: (            最近打开的是 (
遇到 [  → 栈: ( [          最近打开的是 [
遇到 {  → 栈: ( [ {
遇到 }  → 栈顶是 { ✅ 配对，弹出 → 栈: ( [
遇到 ]  → 栈顶是 [ ✅ 配对，弹出 → 栈: (
遇到 )  → 栈顶是 ( ✅ 配对，弹出 → 栈: 空
扫描结束，栈为空 → 匹配 ✅
```

**对比 `"([)]"`：**

```
遇到 )  → 栈顶是 [ ，但 ) 需要 (  → 类型不对，不匹配 ❌
```

### 一个小技巧

**可以用 `switch` 或辅助函数判断：**

```c
static int is_open(char c)  { return c=='(' || c=='[' || c=='{'; }
static int is_close(char c) { return c==')' || c==']' || c=='}'; }
static int match(char open, char close)
{
    return (open=='(' && close==')') ||
           (open=='[' && close==']') ||
           (open=='{' && close=='}');
}
```

**推荐把辅助函数写成 `static`（只在本文件可见）——这叫"内部函数"，不污染全局命名空间。**

## 💡 常见坑

| 坑 | 后果 |
|---|---|
| `stack_pop` 先取再减 | 读到越界元素 |
| `stack_top` 忘了 `-1` | 读到越界元素 |
| **队列出队到空后没清 `rear`** | **下次入队写到已释放的内存 → 崩溃** |
| `queue_push` 忘了更新 `size` | 后续判断全错 |
| 入队时忘了两种情况分开处理 | 空队列时 `q->rear->next` 崩 |
